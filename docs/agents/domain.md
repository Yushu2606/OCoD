# Domain docs

This repository has a single domain context.

- Before exploring the codebase, read the root `GLOSSARY.md` and the ADRs in `docs/adr/` relevant to the task. If either source is missing, continue with the available material.
- Use the glossary's terms in issues, proposals, and tests. Note genuine gaps for the domain-modeling skill.
- If a proposal conflicts with an ADR, name the ADR and explain why the decision should be revisited.
