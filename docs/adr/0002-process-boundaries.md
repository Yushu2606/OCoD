# 将运行时划分为守护进程、角色进程和启动器

守护进程由各角色共享，负责监测全局信息。角色进程管理单个角色的状态。启动器可随角色分发给用户，负责拉起已安装的守护进程和角色进程，在缺失时安装所需的运行时，也可以更新自身。对已经分发的历史启动器采取尽力兼容策略，由各版本决定支持范围。

每个系统用户有一套共享运行时。全局守护进程、角色运行时和库级守护进程各有自己的可执行文件和版本，可独立发布。全局守护进程管理共享运行时的更新，也负责自身更新。新版可在后台准备。切换组件版本前，等待依赖这些组件的角色和管理窗口全部关闭，以及相关库级守护进程完成写入并退出。全局守护进程自身切换后重启。

各组件发布时声明与其他组件的兼容版本范围。全局守护进程据此动态选版，启用满足各组件兼容声明的版本组合。

更新时保留上一套可用版本组合。新版通过启动检查后才完成切换。启动检查失败时，自动恢复上一套可用版本组合并提示用户。

当当前运行时接受启动请求时，启动器先启动角色，再在后台检查并应用可用的启动器更新。自更新不阻塞角色启动。

首次启动缺少运行时时，默认采用在线安装。在线时，启动器只下载、验证、安装并拉起全局守护进程，由全局守护进程按需获取和安装角色运行时及库级守护进程。

启动器内置全局守护进程、角色运行时和库级守护进程的安装包。三个内置组件各自签名，版本相互兼容。无法联网或下载缓慢而切换到离线安装时，由启动器验证并安装三个组件。已有可用运行时时，普通角色启动可离线完成。

联网下载的运行时、启动器内置的离线运行时，以及守护进程获取的运行时更新，都必须通过 OCoD 发布密钥的签名验证后才能安装。

每个已导入角色最多运行一个实例。重复启动时定位到现有窗口。通过「保留两份」导入的两份角色可以各自运行并独立保存状态。

最后一个角色关闭后，守护进程继续运行并检查运行时更新，同时暂停仅为运行中角色服务的全局监测。

角色运行时提供角色库管理能力。编辑器是面向角色作者的独立应用，有自己的可执行文件，由作者单独安装和启动，可独立发布。

库级守护进程使用独立的可执行文件和版本，由全局守护进程按需安装和更新。它协调角色运行时和管理窗口对角色库的操作，角色进程负责各自的角色状态。每个正在使用的角色库各有一个库级守护进程，由同库的角色进程和管理窗口共享。不同角色库可独立使用和退出。最后一个客户端退出且待提交的写入全部完成后，该库的守护进程自动退出。

库级守护进程是角色库的唯一写入方，统一提交角色状态保存、导入、删除和数据迁移等操作。涉及角色目录和索引的变更一并提交。

库级守护进程意外退出时，角色继续使用已加载的素材响应交互。全局守护进程尝试重启该库级守护进程。恢复连接后保存角色最新状态，并核对中断的导入是否已经提交，避免重复导入。
