# 优先兼容 Bug Clicker 的角色分发格式

OCoD 是 Bug Clicker 的洁净室替代实现，采用 Avalonia.Markup.Declarative 和 Native AOT。角色作者与用户之间传递的格式优先与 Bug Clicker 兼容。

首版对完整角色包（`.cvclk`）、独立部件包（`.cvpart`）和台词文件进行双向验收。对每种交付物，Bug Clicker 导出的文件须能在 OCoD 使用，OCoD 导出的文件也须能在 Bug Clicker 使用。

导入后再导出时，保留首版暂时无法编辑或运行的原作字段和素材。例如，只修改点击台词后，原包里的提醒专用台词仍可在 Bug Clicker 中使用。再导出须遵守角色作者设置的权限。

受保护的 `.cvclk` 在两个方向均须验收三项行为：锁定原始编辑字段、禁止接收者再导出，以及凭作者口令恢复权限。

首版支持导入旧版 `carnovella-clicker` JSON。角色包统一以 `bug-clicker` v1 格式导出。

作者可将平台对应的通用启动器与独立的 `.cvclk` 放在同一个分发包内。同一份 `.cvclk` 可用于 Windows 和 macOS，也可直接导入 Bug Clicker。

再次通过启动器打开同一份 `.cvclk` 时，直接打开当前角色库中上次与该包关联的角色，并沿用其运行设置。Windows 移动整个分发目录后继续使用随行的角色库，macOS 移动启动器后继续使用当前系统用户的共享角色库。

通过启动器首次打开多角色包时，导入包内全部角色，展示可多选的角色列表。启动并记住用户选中的角色，下次通过同一份包打开时直接启动这些角色。

导入 `.cvclk` 时，如果发现重复角色，先询问用户如何处理。能可靠识别作者角色身份时，同一角色的新版或出现在另一份包中也触发提示。缺少可靠标识时，仅在角色内容一致时提示。同名角色可以共存。

对重复角色提供跳过、保留两份和更新现有角色三个选项。同包中的新角色照常导入。

更新现有角色时，保留位置、大小和显示偏好等运行设置，并用新版替换角色内容。如果用户改动过角色内容，先列出会被替换的项目，经用户确认后再应用更新。

确认更新后立即保存新版内容。正在运行的角色继续使用已加载的旧内容，并照常保存运行设置。新版内容在下次启动该角色时生效，管理窗口须告知用户生效时机。
